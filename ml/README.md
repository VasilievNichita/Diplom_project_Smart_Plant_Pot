# Folium: фотографии и обучение собственной сети

Подготовлен локальный цикл: экспорт фото из сайта → каталог и ручная проверка → разделение по физическим экземплярам → обучение → отдельная проверка → распознавание одного снимка. **На настоящих растениях модель ещё не обучена и её качество не измерено.** Синтетический прогон проверяет исправность программы; его результаты не подходят для раздела диплома о точности распознавания растений.

Первая задача — различать три согласованные группы: `chlorophytum`, `tradescantia`, `cactus`. Виды и сорта внутри групп необходимо зафиксировать при сборе. «Кактус» пока является названием группы; сеть не определяет конкретный вид. Диагностика болезней, вредителей и рекомендации об обрезке требуют другого набора данных и отдельной проверки. Видимые признаки из осмотра сохраняются в наборе, но не служат целевыми метками этой модели.

## Что уже работает

- Проверка ZIP из Folium: структура, права использования, коды экземпляров, контрольные суммы и декодирование JPG/PNG/WebP. Не более 4000 записей за подготовку, 110 МиБ на архив с распакованными данными, 10 МиБ и 24 мегапикселя на изображение, минимум 64 пикселя по каждой стороне.
- Исключение точных копий, включая повторно сохранённые изображения с одинаковыми пикселями. Похожие снимки разных экземпляров попадают в список для ручного осмотра. Это подсказка, а не надёжное определение всех копий.
- Приватный HTML-каталог на RU/RO/EN: превью по группам и экземплярам, похожие пары рядом, сохранение/возобновление решений в JSON. Подготовка проверяет каждую пару и соответствие решений текущим фото и разметке.
- Неизменяемый подготовленный набор: RGB, 128 × 128, весь кадр вписан с белыми полями, ориентация EXIF учтена, метаданные камеры в новых PNG не сохраняются.
- Собственная небольшая CNN со случайными начальными весами, обучение на CPU, выбор весов по валидации и отдельный запуск теста. Скачивания готовой модели в коде нет.
- Сохранение настроек, версий библиотек, хешей исходников/данных/весов, истории обучения и отчёта с ошибками по классам.
- Отдельный HTML-отчёт на русском, румынском или английском: график ошибки, состав выборок, матрицы ошибок по фото и экземплярам, сравнение с базовым правилом. Открывается без интернета и не запускает повторное обучение/тестирование.

Сайт хранит фотографии и ручные осмотры; проверка набора, решения по похожим парам и подготовка выборок доступны кнопками в «Фотоосмотры». См. [порядок работы через интерфейс](../docs/photo-workflow.md). **Сайт пока не запускает обучение и не вызывает модель распознавания.** Команды ниже остаются отдельным способом работы на ПК. Результат распознавания не управляет насосами.

## Что снять и разметить

Для стенда остаются три домашних растения. Для проверки распознавания новых растений нужны дополнительные **экземпляры на снимках**, а не дополнительные насосы или обязательная покупка растений.

| Этап | Предлагаемый объём | Что он позволяет проверить |
| --- | --- | --- |
| Отладка сбора | По одному домашнему растению, 10–15 различных кадров каждого | Загрузку, хранение, ручную разметку; качество на новых растениях так не оценить |
| Структурный минимум программы | 3 физических экземпляра каждой группы | По одному экземпляру на train/validation/test; этого недостаточно для убедительной оценки |
| Начальный пилот | Постараться собрать 10–20 экземпляров каждой группы, по 8–12 различных кадров | Получить первые ошибки на независимых растениях и понять, какие данные собирать дальше |

Последняя строка — ориентир организации сбора, не научно обоснованный достаточный размер и не обещание определённой точности. Можно с разрешения фотографировать растения знакомых, учебного кабинета или магазина. Данные из интернета подходят только с понятными условиями использования, подтверждённой группой и возможностью установить экземпляр. Неизвестное происхождение не исправляется придуманным кодом.

1. Дать каждому физическому растению постоянный код: например, `home-chl-01` или `classroom-trad-03`. Перестановка горшка, новый день, смена фона, пересадка и канал полива код не меняют. Не считать черенки и соседние кадры независимыми растениями без продуманного протокола.
2. Для классификации снимать общий вид растения и часть кроны, где группа различима. Несколько ракурсов, обычный комнатный свет, разные фоны и дистанции; не набирать десятки практически одинаковых кадров серией. Сильно смазанные фото, коллажи и изображения с надписями не отбирать.
3. Во всех трёх группах использовать похожий диапазон условий: например, не снимать только кактусы на белом столе, а остальные растения только на подоконнике. Иначе фон может подсказывать ответ.
4. Макрофото пятен и насекомых хранить для осмотра. Если по такому кадру нельзя подтвердить группу растения, не включать его в текущий набор классификации. Не повреждать растения ради примеров болезни.
5. На сайте открыть «Фотоосмотры» в режиме «Мои наблюдения», загрузить файл, затем «Осмотреть и разметить»: подтвердить группу, отметить пригодность, указать код экземпляра и источник. Для чужого снимка записать ссылку и основание разрешённого использования. Отметить включение в набор и сохранить.
6. Скачать ZIP и хранить в `datasets/exports/`. Оригиналы могут содержать EXIF/GPS; фотографии, архивы, разметка, веса и отчёты экспериментов остаются приватными. Подробности интерфейса — в [инструкции по фото](../docs/photo-workflow.md).

Сайт экспортирует весь отобранный набор реального режима; фильтры карточек не меняют экспорт. Чтобы выгрузить несколько частей до 100 МиБ, нужно менять отметки отбора и сохранять каждый архив отдельно. Не удалять уже снятые фото ради деления на части. При подготовке передать все нужные архивы вместе. Повторяющиеся записи должны иметь одинаковую разметку; после исправления осмотра исключить устаревший экспорт с тем же ID.

## Окружение

На этом ПК уже создано `ml/.venv` и проверена CPU-версия. Заново устанавливать окружение здесь не требуется. На другом Windows-ПК с Python 3.12:

```powershell
cd D:\diplom
py -3.12 -m venv ml/.venv
.\ml\.venv\Scripts\python.exe -m pip install -r ml/requirements.txt
```

Проверенная конфигурация: Python 3.12.14, PyTorch 2.14.1+cpu, NumPy 2.3.5, Pillow 12.3.0, Matplotlib 3.11.2 для графиков. Если окружение создано до добавления отчётов, повторить установку из `ml/requirements.txt` внутри существующего `.venv`. PyTorch предоставляет тензоры, слои, автоматическое вычисление градиентов и оптимизатор; архитектура и цикл обучения описаны в этом проекте. Это обучение с нуля, но не написание всей математической библиотеки с нуля.

Параметр `--device cuda` предусмотрен, но GPU в этой конфигурации не проверялся. Установленный CPU-пакет CUDA не поддерживает. Для отдельного GPU-окружения выбирать сборку под доступную видеокарту по [официальной инструкции PyTorch](https://pytorch.org/get-started/locally/), затем повторять тесты. Время настоящего обучения измерим на первом реальном наборе; скорость короткого синтетического прогона на него не переносится.

## Команды после сбора фотографий

Все команды ниже выполняются из корня `D:\diplom`. Имена архивов — примеры: сначала сохранить туда свои выгрузки. Выходные папки/отчёты должны быть новыми; команды не перезаписывают существующие результаты.

### 1. Каталог и ручная проверка

```powershell
.\ml\run.cmd inspect --archive datasets/exports/batch-01.zip datasets/exports/batch-02.zip --out private/photo-review/v1 --language ru
```

Открыть `private/photo-review/v1/review.html` обычным браузером. Интернет и сервер не нужны. Рядом создаются `audit.json` и страницы `catalogue-001.html`, `catalogue-002.html` и т. д., по 60 кадров на страницу. Держать папку целиком, чтобы ссылки продолжали работать. Для румынского или английского создать отдельную папку с `--language ro` или `--language en`.

В каталоге проверить группу и постоянный код каждого растения. Превью — те же RGB 128 × 128, которые получает сеть: весь кадр вписан с белыми полями, EXIF не перенесён. Мелкие детали и происхождение проверять по оригиналам; уменьшенное изображение само по себе не доказывает, что растения разные. Ссылки на источники и разрешения в HTML не включаются, они остаются в исходном манифесте.

Если найдены похожие кадры с разными кодами, для каждой пары выбрать решение:

- **Подтверждены разные экземпляры** — по оригиналам и происхождению установлено, что это действительно разные растения.
- **Один экземпляр / копия** — исправить код на сайте или снять отбор с копии, повторно экспортировать ZIP и создать новую проверку.
- **Не могу подтвердить** — уточнить происхождение либо исключить спорный кадр из отбора, затем экспортировать заново.

Нажать «Скачать решения JSON». Можно сохранить незавершённый осмотр и продолжить через «Загрузить сохранённые решения». Для подготовки нужны все решения «разные экземпляры» и отметка подтверждения проверки. Изменение решения снимает эту отметку. Скачать и переместить файл из загрузок браузера, например в `private/photo-review/v1/decisions.json`. Страница не изменяет базу сайта, исходные ZIP и не отправляет фото в интернет.

`auditId` связывает решения с содержимым изображений, метками, ревизиями осмотра и правилом поиска похожих пар. После изменения набора старый файл не пройдёт; переименование того же ZIP не требует нового осмотра. Это контроль согласованности файлов, а не доказательство правильности решения человека. Страницы и JSON с результатами осмотра держать приватными: они содержат изображения и коды экземпляров.

Для аудита только в JSON, без каталога:

```powershell
.\ml\run.cmd audit --archive datasets/exports/batch-01.zip datasets/exports/batch-02.zip --out private/photo-audit-v1.json
```

Проверить `errors`, `classes`, `duplicatesOmitted` и `possibleCrossSpecimenDuplicates`. `valid: true` означает корректность файлов и разметки по формальным правилам; `structuralSplitPossible` отдельно показывает наличие хотя бы трёх экземпляров каждой группы. Ни одно поле не означает готовность к достоверной оценке качества.

При ошибках `inspect` всё равно создаёт отчёт для разбора и завершает работу с кодом 2. Это не разрешение на подготовку. После исправления экспортировать новый набор и выбрать новую папку отчёта.

### 2. Зафиксировать выборки

```powershell
.\ml\run.cmd prepare --archive datasets/exports/batch-01.zip datasets/exports/batch-02.zip --out datasets/prepared/v1 --seed 42
```

Если были похожие пары, передать сохранённые решения:

```powershell
.\ml\run.cmd prepare --archive datasets/exports/batch-01.zip datasets/exports/batch-02.zip --out datasets/prepared/v1 --seed 42 --review-file private/photo-review/v1/decisions.json
```

Устаревший, неполный файл, повторяющиеся пары, отсутствие подтверждения, решения «один экземпляр» и «не могу подтвердить» блокируют подготовку до исправления. Когда похожих пар нет, файл решений не нужен. Прежний общий флаг `--reviewed-near-duplicates` удалён. В подготовленном манифесте сохраняются хеш JSON-решений, идентификатор аудита, время и число проверенных пар.

Отчёт ограничен первыми 200 похожими парами; если список обрезан, подготовка блокируется даже с файлом решений. Сначала разобрать перечисленные случаи и повторить проверку. dHash замечает не все копии и иногда ошибается; чистый отчёт не заменяет проверку кодов экземпляров.

Для каждой группы перемешиваются **коды растений**, а не отдельные фото. В тест и валидацию попадает по `max(1, floor(0.2 × число_экземпляров))`, остальные идут в обучение. Получается примерно 60/20/20 по экземплярам; доли фотографий могут отличаться. Все снимки одного экземпляра остаются вместе. Групповой принцип соответствует подходу к непересекающимся группам, описанному в [GroupKFold](https://scikit-learn.org/stable/modules/generated/sklearn.model_selection.GroupKFold.html); здесь реализовано собственное однократное разбиение, а не кросс-валидация этой библиотекой.

`manifest.json` содержит назначение каждого кадра и `datasetId`. Перед обучением проверяются хеши и отсутствие пересечений. Зафиксированный набор не править вручную. При поступлении новых растений создать новую версию, заранее согласовав состав будущего теста: повторное случайное разбиение прежних данных само по себе не создаёт новый независимый тест.

### 3. Обучить с нуля

```powershell
.\ml\run.cmd train --data datasets/prepared/v1 --out ml/runs/pilot-v1 --epochs 30 --batch-size 16 --seed 42 --patience 8 --device cpu
```

`FoliumCNN` (`folium-cnn-v1`) содержит 79 475 обучаемых параметров. Четыре блока Conv 3×3 → GroupNorm → ReLU → MaxPool имеют 16, 32, 64, 96 каналов. Затем идут усреднение пространственных признаков, Dropout 0.15 и линейный слой трёх классов. Это простая исходная архитектура для исследования, без заявления о научной новизне самих слоёв.

Начальные веса случайные. Оптимизатор AdamW, cross-entropy, начальная скорость обучения 0.001. Только для обучающих кадров применяются отражение по горизонтали и небольшое изменение яркости. Изображения validation/test не аугментируются. Лучшие веса выбираются по минимальной ошибке валидации; 8 эпох без улучшения останавливают обучение. Параметры и номер лучшей эпохи сохраняются.

`train` читает файлы всех выборок для проверки целостности, но **не использует тестовые изображения для градиентов, метрик или выбора весов**. Перебирать параметры можно по валидации, не по итоговому тесту. Фиксация seed помогает повторять расчёт в том же окружении; идентичность между разными версиями библиотек, CPU и GPU не гарантируется — это ограничение описано в [документации PyTorch о воспроизводимости](https://docs.pytorch.org/docs/2.14/notes/randomness.html).

### 4. Оценить выбранную модель

```powershell
.\ml\run.cmd evaluate --data datasets/prepared/v1 --run ml/runs/pilot-v1
```

Выполнить после завершения выбора архитектуры и настроек. `test-report.json` включает accuracy, macro-F1, balanced accuracy, precision/recall/F1 по группам, матрицу ошибок и предсказания. Отдельно показан результат по физическим экземплярам: усредняются оценки их кадров, и каждое растение имеет одинаковый вес. Простой ориентир для сравнения всегда предсказывает наиболее частый класс **обучающей** выборки.

Повторная запись тестового отчёта для этого запуска блокируется. Это защита от случайного повторения, а не техническая гарантия исследовательской независимости: копирование папок и выбор «лучшего» запуска по тесту всё равно нарушат протокол. После изучения тестовых ошибок его нельзя продолжать представлять как неизвестный модели критерий выбора следующей версии. В дипломе указывать число тестовых фото **и экземпляров**, состав групп, все ограничения и фактически полученные значения, даже если они низкие.

### 5. Попробовать отдельное фото

```powershell
.\ml\run.cmd predict --run ml/runs/pilot-v1 --image private/new-plant.jpg --threshold 0.7
```

Команда возвращает оценки трёх классов и `uncertain`, если максимум ниже порога. Значение 0.7 — начальная настройка, не проверенный порог и не гарантия правильности 70%. Оценки softmax не откалиброваны; неизвестное растение или вообще посторонний предмет может получить высокую оценку. Для использования на сайте потребуются проверка таких случаев, выбор порога по валидации и подтверждение пользователем. Для синтетической модели решение всегда `synthetic_test_only`.

### 6. Открыть понятный отчёт с графиками

```powershell
.\ml\run.cmd report --run ml/runs/pilot-v1 --out private/reports/pilot-v1-ru.html --language ru
```

Открыть сохранённый HTML в браузере. Для другого языка указать `--language ro` или `--language en` и новое имя файла. Отчёт содержит встроенные графики, не требует сервера, подключения к интернету или внешних шрифтов. Графики строятся Matplotlib; для повторного отображения сохранённого HTML Python не нужен.

Команду можно выполнить **до** `evaluate`: тогда показаны ход обучения и явный статус «тест ещё не выполнен». Итоговые метрики появятся только в новом HTML, созданном после отдельной оценки. Создание отчёта читает сохранённые результаты и веса для проверки хеша; оно не загружает модель в PyTorch, не открывает фотографии и не пересчитывает предсказания. Нельзя оценить прогресс по отсутствующему отчёту как нулевую точность.

Проверяются принадлежность теста тому же набору/весам, согласованность матриц с предсказаниями, метрики классов, выбранная эпоха и хеш истории в новых запусках. У старых запусков отсутствующие сведения о числе экземпляров и хеше истории отмечаются как отсутствующие, без догадок. Эти проверки выявляют несогласованные файлы; они не доказывают правильность человеческой разметки и не заменяют независимый исследовательский протокол.

Синтетическое происхождение явно обозначено в HTML и заголовках самих графиков. В итоговый HTML не копируются фотографии, заметки, ссылки на источники и коды экземпляров. Хранить его в `private/` рядом с материалами опыта; веса и наблюдения по-прежнему не публикуются.

## Как проверить код без настоящих фотографий

```powershell
cd D:\diplom\ml
.\.venv\Scripts\python.exe -m unittest discover -s tests -v
cd ..
node --test ml/tests/inspection-ui.test.mjs
.\ml\run.cmd smoke --out private/ml-smoke-new-run
```

Smoke создаёт цветные шумовые изображения, затем действительно обучает сеть две эпохи, сохраняет веса, проверяет отдельную выборку и повторно загружает модель. Пометка `synthetic-smoke-test` проходит через весь цикл; смешивание таких изображений с реальными архивами блокируется. Эти проверки не дописывают записи в рабочую базу сайта.

Для JavaScript-проверок нужен Node.js 24+, как и для сайта; если `node` не добавлен в PATH, указать полный путь к установленному Node. Они проверяют черновики, загрузку, смену решений и блокировку устаревшего файла. Python-тесты дополнительно проверяют привязку решений к набору, запрет неполной проверки, каталог на трёх языках и отсутствие EXIF в превью.

## Файлы и следующий этап

| Файл | Назначение |
| --- | --- |
| `folium_ml/data.py` | Аудит, копии, нормализация, независимые группы и целостность |
| `folium_ml/inspection.py`, `inspection_copy.py`, `inspection_ui.mjs` | Автономный каталог и ручные решения по похожим парам на трёх языках |
| `folium_ml/model.py` | Собственная архитектура сети |
| `folium_ml/training.py` | Обучение, оценка и одиночное предсказание |
| `folium_ml/metrics.py` | Общий расчёт метрик для оценки и проверки отчётов |
| `folium_ml/reporting.py`, `report_copy.py` | Проверяемый автономный HTML с графиками и текстами на трёх языках |
| `folium_ml/smoke.py` | Только синтетические программные проверки |
| `tests/` | Проверки разделения, ошибок данных, метрик, обучения и весов |
| `configuration.json`, `history.json` в папке запуска | Настройки и реальные кривые обучения по эпохам |
| `model.pt`, `model.json` в папке запуска | Веса и их происхождение |
| `test-report.json` в папке запуска | Итоговая оценка на отложенной выборке |
| HTML в `private/reports/` | Просмотр сохранённого запуска, без повторного обучения и оценки |
| `review.html`, `catalogue-*.html`, `audit.json` в `private/photo-review/` | Приватный осмотр фотографий перед подготовкой выборок |

Ближайший шаг — собрать и проверить первую партию фото. Затем можно измерить скорость обучения, качество по каждой группе и ошибки на незнакомых предметах. Только после этого подключать проверенную модель к фотоосмотру сайта. Прогноз полива по датчикам и диагностика болезней — отдельные задачи; этот классификатор их не решает.
