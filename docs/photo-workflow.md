# Как работать с фотографиями в Folium

Серверный контракт: [photo-api.md](photo-api.md). Этот документ объясняет работу интерфейса фотоосмотров. Код обучения с нуля уже подготовлен локально, но модель на реальных растениях пока не обучена.

## Первый осмотр

1. После обновления исходников перезапустить локальный сервер и обновить страницу. В «Настройки» выбрать «Мои наблюдения».
2. В «Фотоосмотры» нажать «Добавить фото». Выбрать растение, JPG/PNG/WebP до 10 МБ и при желании записать заметку. HEIC сначала преобразовать в поддерживаемый формат. Доступ с телефона по сети пока требует отдельного этапа настройки доступа; сейчас сайт работает на самом ПК.
3. Открыть «Осмотреть и разметить». Подтверждать растение только если оно определено уверенно. Класс «Кактус» не означает определения конкретного вида. При ошибке назначения загрузить снимок с правильным растением; старый не отбирать в набор.
4. Отметить пригодность изображения и только видимые признаки. Если оценить нельзя, оставить «Не могу оценить». Отсутствие видимых изменений не является диагнозом «здоров».
5. Сохранить осмотр. Можно оставить неизвестными экземпляр/источник и не включать фотографию в набор. Фильтры помогают находить такие незавершённые записи.

## Отбор для собственной модели

Для отбора нужны подтверждённое растение, пригодный снимок, код экземпляра и источник. Код относится к физическому растению: `home-chl-01` остаётся тем же при смене дня, освещения, ракурса и канала полива. Другому экземпляру дать отдельный код. Для чужого изображения записать страницу-источник и разрешение/лицензию; если условия или личность экземпляра неизвестны, пока не отбирать.

Поставить отметку «Включить фото в набор для обучения» и сохранить. Подсказка укажет, чего не хватает. Фотографии из «Демонстрации» всегда исключены. При конфликте правок в двух вкладках закрыть форму, обновить страницу и повторно проверить поля.

«Скачать учебный набор ZIP» выгружает оригиналы и `manifest.json`. Отбор относится ко всему набору реального режима, а фильтры меняют только показанные карточки. Точные повторы выгружаются один раз; количество пропущенных повторов видно в счётчике. Архив до 100 МиБ; большие наборы выгружать частями, сохраняя общие коды экземпляров. Оригиналы могут содержать метаданные камеры, поэтому архив хранить приватно. Ни фото, ни разметку наблюдений не публиковать в GitHub.

## Что подготовить для обучения

### Проверка прямо на сайте

В «Фотоосмотры» → «Мои наблюдения» появился блок **«Проверка набора перед обучением»**. После первоначальной установки Python-окружения по `ml/README.md` проверку и подготовку можно запускать кнопками, без ручного ввода команд.

1. Отобрать пригодные фото через «Осмотреть и разметить», указав реальный код физического экземпляра и источник.
2. Нажать **«Проверить текущий отбор»**. Сервер проверяет весь отбор, независимо от фильтров карточек. Можно уйти со страницы: работа продолжается, результат появится при возвращении.
3. Просмотреть ошибки, каталог и похожие пары. Открыть оригиналы и при необходимости перейти прямо к разметке снимка. Превью показывают вход сети 128 × 128; по ним нельзя подтвердить все мелкие детали.
4. Для каждой пары выбрать «разные экземпляры», «одно растение / копия» или «не могу подтвердить». **«Сохранить решения»** сохраняет и незавершённый осмотр на сервере. Любое изменение решения снимает подтверждающую отметку.
5. Для совпадений и сомнений исправить код/отбор в карточке фото, затем запустить новую проверку. Старые решения автоматически не переносятся. Если другая вкладка изменила решения, сервер отклоняет устаревшее сохранение.
6. После завершения осмотра нажать **«Подготовить выборки»**. Кнопка доступна при отсутствии ошибок, полном разборе пар и минимум трёх независимых экземплярах каждой группы. Получаются неизменяемые train/validation/test с seed 42; все снимки одного экземпляра остаются вместе. Обучение и полив эта кнопка не запускает.

Текущий результат и решения сохраняются в SQLite. Снимок исходного ZIP, превью и подготовленные изображения — в `data/photo-inspections/<идентификатор>/` рядом с базой. Это приватные файлы вне публичной папки сайта. SQLite-резервная копия содержит оригиналы фото и решения, но **не отдельные файлы проверки/выборок**: для полного восстановления сохранять также `photo-inspections`. При отсутствии снимка проверку нужно выполнить заново. Старые снимки проверок сохраняются отдельно, в том числе после удаления фото из библиотеки; их удаление не входит в действие удаления карточки.

Одновременно выполняется одна задача, предел исполнения — две минуты. Прерывание сервера помечает незавершённую задачу как неудачную; автоматически она не возобновляется. При недоступном окружении Python или ошибке подготовки сайт показывает сообщение, а не успешный результат.

Внешние фотографии, найденные в интернете, добавляются как кандидаты с источником, автором и лицензией. Они не являются домашними наблюдениями. Нельзя присваивать каждому файлу новый код экземпляра только ради прохождения минимального числа растений.

### Материалы для сбора

- Свои фотографии трёх растений: общий вид, листья с двух сторон и крупные планы изменений. Использовать ровный свет, избегать фильтров, сохранять реальные наблюдения без намеренного повреждения растений.
- Проверенные изображения других физических экземпляров тех же групп с правом использования. Три домашних экземпляра позволяют проверить работу стенда; они не доказывают распознавание новых растений.
- Проверку подписей и похожих кадров. Сервис убирает точные повторы, но не распознаёт переобработанные копии и не знает, что разные коды были ошибочно присвоены одному растению.

После сбора данных использовать [локальный модуль обучения](../ml/README.md): в нём уже реализованы проверка изображений, поиск копий, разделение по экземплярам, собственная небольшая сеть со случайными начальными весами и отдельный отчёт по тестовой выборке. Там же описаны объём пилотного сбора и команды запуска. Кнопка экспорта на сайте не запускает обучение автоматически.

Перед подготовкой выборок команда `inspect` создаёт приватный каталог с уменьшенными фото и сравнением похожих пар. На каждой паре можно отметить разные экземпляры, один экземпляр/копию или сомнение; решения сохраняются в JSON и могут быть загружены для продолжения. `prepare --review-file` принимает только завершённую проверку именно текущего набора. При ошибке кодов исправлять осмотр на сайте, затем экспортировать новый ZIP. Каталог не меняет записи сайта. Подробные команды — в разделе «Каталог и ручная проверка» инструкции модуля обучения.

Никакие текущие счётчики фото не являются точностью модели или обещанием её качества. Для диагностики причин болезни нужны отдельные проверенные метки и отдельная оценка — текущие видимые признаки их не заменяют.

Код физического экземпляра и ограничения оценки подробнее объяснены в [серверной документации](photo-api.md#состав-учебного-набора). Выбор фото не обучает сеть, не включает насос и не создаёт рекомендации о препаратах, обрезке или поливе.
