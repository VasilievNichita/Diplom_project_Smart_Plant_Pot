# Folium: прошивка и сборка ESP32

Базовая плата: **ESP32 DevKit с классическим ESP32-WROOM-32 / 32E**, 4 MB flash. ESP32-C3, S2, S3, ESP8266 и платы с другой разводкой требуют отдельного переноса. Использовать надписи GPIO на плате, а не номера ножек разъёма. Прошивка подготовлена до покупки деталей; физические испытания ещё не выполнены.

- [Подробная сборка, калибровка и испытания](../docs/hardware-assembly.md).

## Что реализовано

Два аналоговых входа для почвенных проб; SHT31 (температура/влажность воздуха), BH1750 (свет), поплавковый контакт уровня; два активных HIGH выхода на MOSFET. Установлены 12 бит ADC и ослабление 11 dB. Телеметрия раз в 15 секунд, конфигурация примерно раз в секунду, запрос команд раз в 2 секунды. При сбоях интервалы увеличиваются на время запроса. Показания не подменяются демонстрационными числами: отсутствующие/ошибочные значения отправляются как `null`.

Это **ограниченный полив по команде оператора**. Автономное расписание, агрономические пороги и решения ИИ здесь ещё не включены. ПК с сервером должен работать; без него полив не начинается.

Программные ограничения:

- Один насос одновременно, команда максимум 30 секунд; локальная общая пауза минимум 60 секунд после остановки и серверные пределы дозы/суток/паузы.
- После загрузки нужно сначала OFF, затем RUN физического переключателя. Замкнутый при старте RUN сам ничего не разрешает. Вода должна давать замкнутый контакт минимум 0,5 секунды, RUN - минимум 1 секунду.
- Независимая задача FreeRTOS проверяет насос примерно каждые 5 мс, ADC - примерно каждые 100 мс. Она не выполняет HTTP и не пишет flash. Потеря воды, разрешения, исправного сигнала пробы, Wi-Fi или успешного контакта с сервером останавливает текущий импульс.
- Пропажа контакта с сервером: запрос имеет тайм-аут; при обнаруженной ошибке разрешение снимается, крайний срок свежести успешной конфигурации - 6 секунд. Зависание основного цикла дольше 4 секунд также останавливает импульс. Watchdog задачи настроен на 3 секунды с перезагрузкой. Это программные механизмы, их задержки на реальной плате ещё нужно измерить.
- Приём команды записывается и перечитывается из NVS **до** включения. Сохраняются последние 16 идентификаторов и неотправленный результат. Дополнительно проверяются срок, версия привязки, растение, проба, калибровка, расход и доза. Сервер сам выдаёт каждую команду один раз.
- После пропадания питания незавершённая команда не повторяется. Её длительность не выдумывается: оператор проверяет стенд и разрешает неизвестный результат в настройках сайта. Прошивка получает это решение с сервера только при физическом OFF.
- NVS повреждена/не записывается - выходы заблокированы. Нельзя стирать NVS как обычный способ снять блокировку; сначала проверить насосы и согласовать неизвестные команды с сервером.

Задача и watchdog работают на том же микроконтроллере и не являются независимой аппаратной защитой. MOSFET может отказать замкнутым. SW1.A физически разрывает питание насосов. Стенд сначала испытывается под наблюдением, с небольшим запасом воды и поддоном.

## Сборка и прошивка

Проект PlatformIO. Закреплены Espressif32 6.9.0 и Arduino-ESP32 2.0.17; это проверяемая базовая версия, не утверждение о самой новой. Используются штатные WiFi, HTTPClient, Wire, Preferences и cJSON из ESP-IDF; внешних библиотек датчиков нет.

Из `firmware`:

```powershell
pio run -e monitor
pio run -e pump-test
pio run -e irrigation
```

На этом ПК PlatformIO уже установлен. Если `pio` отсутствует в PATH, вместо него:

```powershell
& "$env:USERPROFILE\.platformio\penv\Scripts\pio.exe" run -e monitor
```

| Профиль | Назначение | Насосы |
|---|---|---|
| `monitor` (по умолчанию) | Первое включение, ADC, датчики, связь, калибровка | Программно отключены, команды не забираются |
| `pump-test` | Измерение расхода в мерную ёмкость по USB | Только вручную по Serial, 100-5000 мс, пауза 2 с; вода и RUN обязательны |
| `irrigation` | Полив по команде сайта | После калибровки, разрешения в сайте и физического RUN |

Для загрузки подключить только свою ESP32, определить порт (`pio device list`), поставить SW1 в OFF и отключить блок насосов. Пример **с заменой COM-порта**:

```powershell
pio run -e monitor -t upload --upload-port COM5
pio device monitor --port COM5 --baud 115200
```

Если плата не входит в загрузчик, удерживать BOOT на этапе подключения загрузчика, отпустить после начала записи. Разъёмы USB и драйверы USB-UART зависят от купленной платы. После прошивки проверить, что строка запуска содержит ожидаемый профиль.

## Настройка сети

1. Сначала запустить сервер и зарегистрировать ESP32 по [инструкции API](../docs/api.md). Сам файл прошивки не создаёт ключ и не регистрируется анонимно.
2. Скопировать `include/secrets.example.h` в `include/secrets.h`. Вписать Wi-Fi 2,4 GHz, числовой частный IPv4 ПК, порт 4174, `deviceId` и ключ из `private/esp32-main.json`.
3. Включить отдельный слушатель устройств на сервере, при необходимости разрешить его только в частной домашней сети. Закрепить IP ПК через DHCP роутера. Не использовать `127.0.0.1` в ESP32: это адрес самой платы.
4. Собрать/прошить `monitor`, проверить новые измерения в реальном режиме сайта. Без заполненного файла доступны только локальные показания в Serial.

`secrets.h` и `.pio` исключены из Git. Прошивка с настоящими ключами также содержит пароль Wi-Fi и ключ устройства: её бинарники нельзя публиковать. Непривилегированный HTTP допустим только для доверенного тестового LAN; для внешней сети нужны TLS и отдельная настройка доступа. Проброс портов роутера не требуется.

## Калибровка помп

Сначала собрать защитную обвязку и проверить OFF. Прошить **`pump-test`**. Выходы трубок направить в мерную ёмкость; входы погрузить в воду. OFF -> RUN, выждать секунду. В Serial Monitor отправлять с переводом строки:

```text
pulse 1 1000
pulse 2 1000
```

Каждая строка - отдельный запрос. Дождаться `OFF ... local_timer`, измерить объём. Для более точного отсчёта после заполнения трубки можно использовать `pulse 1 5000` и 3-5 повторов с паузами. Объём заполнения пустой трубки в расход не включать. `мл/с = сумма измеренных мл / сумма фактических секунд`. Не принимать `water`, `disabled`, `timing` и другие остановки за успешный опыт. Эта прошивка не пишет калибровочные опыты в сервер автоматически; сохранить измерения вручную в журнале.

После измерения расхода поставить OFF, прошить `monitor` для почвенной калибровки либо `irrigation` для заключительных испытаний. Не оставлять профиль `pump-test` на итоговом стенде.

## Проверки без платы

```powershell
.\scripts\test-native.ps1
```

Нужен host C++ компилятор `g++`; можно передать `-Compiler` с путём. Это настоящие C++ тесты того же заголовка, который компилируется для ESP32: таймер, аварийные условия, длительный uptime, контакты, CRC датчика, калибровка, UTC, повтор команды и повреждение записи. Они не эмулируют электрические цепи, Wi-Fi-драйвер или NVS flash.

Из `site` дополнительно `npm test` и `npm run simulate`. Реальные испытания перечислены в инструкции сборки; успешная компиляция не заменяет их.

## Файлы

- `src/main.cpp`: API, конфигурация, NVS, цикл устройства.
- `src/pump.cpp`: отдельная задача, GPIO, контакты, ADC, watchdog.
- `src/bench.cpp`: ручной режим измерения расхода без сервера.
- `src/sensors.cpp`: драйверы I2C с проверкой CRC SHT31 и отсутствующих данных.
- `include/folium_core.h`: проверяемая логика без зависимости от Arduino.
- `include/board.h`: единая карта GPIO.

Ни один режим не измеряет фактический поток воды: нет расходомера/датчика тока. Пустая трубка, пережатие, утечка и насос, не вращающийся при исправном GPIO, пока определяются осмотром и контрольным измерением.
